## Architecture (current — decision tiers, not additive points)

Four engines, each producing its **own tier** (LOW / MEDIUM / HIGH); the **verdict is the highest tier any engine reaches**. Score-adding across unlike evidence was dropped: on honest data it left 67.8% of unseen phishing URLs LOW (ROC-AUC 0.598) and 99% of legitimate texts MEDIUM.

| Engine | Input | Tiers |
|---|---|---|
| `rule_based` | URL and/or text | URL part: MEDIUM >= 40, HIGH >= 90. Text part: MEDIUM >= 30, HIGH >= 60. Sub-engines combined by noisy-OR |
| `blacklist` | URL | exact match = HIGH; domain match = MEDIUM (shared-hosting domains suppressed at domain level) |
| `url_model` | URL | ensemble of char-TF-IDF LogReg + LightGBM; MEDIUM p >= 0.666 (1% FPR on validation), HIGH p >= 0.983 (0.1% FPR) |
| `text_model` | text | character TF-IDF + LogReg; MEDIUM p >= 0.252 (5% FPR), HIGH p >= 0.784 (1% FPR); thresholds from non-synthetic validation messages (synthetic rows excluded, see `export_models.py`); re-estimate once collected real messages exist |

- Display score maps tiers to bands 0–33 / 34–66 / 67–100. The Egyptian-brand allowlist cancels **URL-derived** signals only (never message text) for verified exact/subdomain hosts.
- `/analyze` returns `engine_tiers` and `decided_by` (the old `weighted_contributions` is gone); explainability fields (`skip_reasons`, `stage_timings`) are additive.
- The BiLSTM is **no longer in the live path**; it is kept as a documented comparison (Ch. 3.8 / 5.3). Default assumption until the supervisor says otherwise: character model live, BiLSTM compared. **Open question:** does the supervisor require a deep-learning model in the live text engine?
- Code: `backend/app/engines/risk_scoring.py` (scorer), `engines/rule_based/` (Arabic + English keyword, domain typosquatting, URL pattern, combiner), `engines/threat_intel/blacklist_lookup.py`, `engines/ml/` (`url_features.py`, `url_model_inference.py`, `text_char_inference.py`). ## Rule-engine details worth remembering (`domain_typosquatting_detector.py`)

Techniques in order of confidence: exact match (0), domain embedding (95), userinfo/backslash embedding, homoglyph/confusable (92, runs BEFORE Levenshtein), Levenshtein (60–90, only brand domains >= 9 chars), brand-label reuse (70), and (2026-10): `brand_token_combo` (70/60), `brand_hyphen_split` (70), `brand_tld_swap` (60), `brand_in_path` (60, capped MEDIUM). New techniques never reach HIGH (>= 90) alone. Brand aliases (`cib`, `qnb`, `bankmisr`, `eand`) live in `egyptian_brands.py` and come from official names, not from any test set. Multinational labels (vodafone, orange, amazon, etisalat, jumia, talabat, noon, qnb) are not flagged on ordinary country-code/.com suffixes (fixed false positives on `vodafone.com`, `amazon.de`, `etisalat.ae`). Known cost: `amazon.work` (abuse-prone TLD) is flagged MEDIUM; it was a legitimate row in the test set. Any legitimate alternate brand domain must be added to the registry or it is treated as a swap.

`url_pattern_analyzer.py`: `no_https` only for an explicit `http://`; unparseable URLs (`javascript:`, bad ports) return a `malformed_url` flag (no HTTP 500); `@` counts only in the host part. `url_model_inference.ensure_scheme()` scores scheme-less input as `https://` (without it `wikipedia.org` scored 0.46; with it 0.003). **Known model limit:** the URL model reads `http://` as suspicious (legitimate `http://` URLs: 4/39 flagged = 10.3% vs 0.8% for others; phishing recall 89.5% on `http://` vs 96.0%). State in Chapter 7.

## Known limits to state in the thesis

Blacklist value on already-known threats is not measurable in the eval DB; no Egyptian-brand URLs in the dataset (benchmark is constructed); legitimate URLs are Tranco top-20k + crawled pages (precision on obscure sites unmeasured); text test set is small (82 phishing / 193 legitimate; 67% is one translated Kaggle set; only 16 mixed and 16 dialectal legitimate messages); real legitimate Egyptian SMS (bank, wallet, delivery, OTP) are missing; URLs with a path have ~2.8% FPR; `http://` shortcut; keyword/LLM-style false positives on anti-fraud warnings (Al-Ahly advisory); BiLSTM edge disappeared on the honest split; shared-platform URLs must be reported separately; English text is covered by rules only (the text model has essentially never seen English phishing). The URL model scored the genuine `https://www.cibeg.com/` at 95.45% and `https://www.cibeg.com/login` at 69.29% (above the 66.6% MEDIUM threshold); both observed in browser scans on 2026-10-19/20, two URLs only. Only the Egyptian-brand allowlist makes them LOW, so the allowlist is load-bearing (how many allowlisted brand URLs the model would flag without the override is **not yet measured**). A URL with no host (`https://`) used to score LOW (4.53); since commit c4c9ed5 `ensure_url_has_host()` (`app/core/url_validation.py`, called from `risk_scoring.py`) rejects it with a 400, while unparseable-but-hosted inputs (`javascript:`, bad port, broken IPv6) keep their `malformed_url` handling.

Held-out typosquat findings to state in Chapters 5 and 7 (2026-10-22): dev-set results overstate generalisation to unseen vocabulary (class D only 43.5% [38.7, 48.4]); the context-word list drives the combo/subdomain rules (novel keywords 66.6% vs 84.1%); short brands (te.eg 37.0%) are a structural ceiling because Levenshtein only applies to brand domains of 9+ characters; the URL model flags 7 of 36 real popular Egyptian-site URLs at MEDIUM (none HIGH; effective n = 18 domains, list written from memory, so this needs a larger verified measurement); namesake collisions such as `cibc.com` are flagged by the rule engine.

## Environment gotchas

- `uvicorn` / `pytest` from `backend\` (`No module named 'app'` otherwise).
- `DATABASE_URL`: a placeholder or bracketed password makes every URL row fail with `password authentication failed` while text rows still work (text never touches the DB). The env var is per PowerShell window; without it the code falls back to `.env` (demo DB `etis`) and the evaluation script refuses to run.
- `psql` with Arabic text needs `$env:PGCLIENTENCODING = "UTF8"`.
- Use `Invoke-RestMethod` with a hashtable piped through `ConvertTo-Json` instead of nested-JSON `curl`; add `-Depth 10` to see nested fields.
- `git add`/`git commit` from the project root (from `backend\` the `backend/...` paths do not exist). Commit and `git stash` hygiene: see Working rules.
- Root-level `requirements.txt`; `.env` at the project root. `git` warnings "LF will be replaced by CRLF" are normal.
