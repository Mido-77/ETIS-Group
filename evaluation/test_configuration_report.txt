SCOPE CAVEATS -- include in Chapter 5.3/5.8, do not omit:
- Blacklist-only and LSTM-only are evaluated on DIFFERENT row subsets (URL rows only / text-email rows only respectively), not the full test set. Rule-based-only and full-hybrid ARE evaluated on the full test set. This table is not a clean apples-to-apples comparison without that caveat.
- Blacklist-only (and the blacklist component of full-hybrid) shares the same known limitation as threshold calibration: blacklist_entries was seeded from full PhishTank/OpenPhish feeds, not train-split-only, so some test-split phishing URLs may already sit in the blacklist. This inflates blacklist-driven recall via trivial exact-match rather than pure generalization to unseen phishing. Rule-based-only and LSTM-only do not have this issue.
- Binary threshold (score >= 50) is a plain midpoint split chosen for threshold-neutral comparability across configs, not a calibrated decision boundary for any individual engine -- ROC-AUC is the primary metric that should carry weight in the writeup, not the F1/accuracy numbers in isolation.
